# にてる英語、どっち？

似た英単語の2択を選ぶ、日本語話者の初心者向け英語学習ゲーム。全20問、時間制限・ログインなし。間違えても再挑戦でき、正解後は意味を復習して自分で次に進めます。完了後は問題順と選択肢をシャッフルできます。

HTML / CSS / JavaScript の静的PWAです。実行時の外部ライブラリ・フォント・画像通信・DBはありません。Web Audioの正解音、Web Speech APIの通常 / ゆっくり英文読み上げを備えています。英文を読み上げるのは正解後のボタン操作時だけです。

## ローカル起動

Node.js 24 と Python 3 が必要です（ゲームの配信だけならPython 3のみ）。

```sh
cd /path/to/which-word
npm ci
npm start
```

開く場所は `http://localhost:4173/which-word/`。この起動コマンドは親ディレクトリを配信するため、チェックアウト名を `which-word` にしてください。別名の場合はURLの末尾もそのフォルダ名に置き換えます。開発サーバーは公開用ではありません。

```sh
npx playwright install --with-deps chromium webkit
npm test
npm run build
```

`dist/` がそのまま公開可能なファイル一式です。ビルドはソースを変更しません。既存Chromiumを使う場合は `CHROMIUM_PATH=/usr/bin/chromium npm test -- --project=chromium-mobile`。テスト用サーバーは4173 / 4174を使用します。

## 問題の変更

`questions.js` の配列は `[空欄を___で表す英文, 日本語訳, 正解, もう一つの単語]`。`meanings` に各単語の短い意味を追加してください。例：

```js
['I ___ money.', 'お金を貯めます。', 'save', 'safe']
```

日本語訳を含めて正解が1つになるように確認します（例：have / hateは英文として両方成立しますが「猫を飼っています」に合うのはhaveだけです）。初回は指定順、1問目は safe / save。再プレイでは両方をランダム化します。現在のUI・テストは指定の20問を前提にしています。問題数を変える場合は完了画面・説明文・テストの20問表記も変更してください。

## GitHub Pagesでの公開

リポジトリの公開範囲や課金設定は変更しないでください。現在のプラン・公開範囲でPagesが利用できない場合は管理者に相談してください。

1. GitHubの `Kadogawa1369/which-word` を開き、**Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
2. **Settings → Actions → General** でActionsが許可されていることを確認します。組織の制限がある場合、ワークフロー内の公式Actionsを許可する必要があります。通常、全ワークフローに書き込み権限を与える必要はありません。公開ジョブのみ `pages: write` と `id-token: write` を指定しています。
3. `.github/workflows/pages.yml` を含むコードを `main` へプッシュします。プッシュ済みなら **Actions → Test and deploy PWA to Pages → Run workflow → Branch: main → Run workflow** を実行します。
4. `test-build` がChromium / WebKitテストとビルドを実行し、成功後に `deploy` が `dist/` を公開します。`github-pages` 環境の承認を求められた場合は、デプロイ画面から所有者が承認してください。
5. **Actionsの実行結果のdeployジョブ / github-pages環境** または **Settings → Pages の Visit site** に表示されるURLを開きます。カスタムドメイン未設定なら想定URLは `https://kadogawa1369.github.io/which-word/` です。この記載自体は公開完了の証明ではありません。
6. 実際のURLでゲーム、`manifest.webmanifest`、`sw.js`、`icons/icon-192.png`、`icons/icon-512.png`、`icons/apple-touch-icon.png` が200で配信されること、20問の進行とオフライン準備完了を確認してください。

`start_url` / `scope` / HTML参照 / Service Workerのキャッシュ対象は相対パスで、`/which-word/` の下で完結します。公開物にソース管理情報、node_modules、テストサーバーは含めません。

## 更新

1. コード・問題を変更したら `sw.js` の `VERSION` を必ず一意な新バージョンへ変更（例：`which-word-v2`）。新しい配信ファイルは `ASSETS` にも追加します。
2. `npm test` と `npm run build` を実行し、mainへプッシュ。
3. 次回オンライン接続でブラウザが更新を検出すると更新ボタンを表示します。利用者が押すまで解答画面は強制リロードされません。更新すると最初からのプレイになります。
4. 新workerの有効化時に、このアプリの古いキャッシュだけを削除します。通信失敗で新キャッシュの作成が完了しなければ旧版を維持します。

## iPhoneでの確認

1. 公開完了したHTTPS URLを **Safari** で開き、「オフライン準備完了」を待ちます。
2. 共有ボタン → **ホーム画面に追加** → **追加**。ホーム画面の本・チェックマークのアイコンから開き、Safariのアドレスバーがないstandalone表示を確認します。
3. 第1問でsafeを選び再挑戦、saveで正解すること、空欄が埋まることを確認。「効果音 ON」でピンポン音、OFFで無音になることを確認。iPhoneの音量・消音設定も確認します。
4. 正解後に「英文を聞く」「ゆっくり聞く」を押し、英文だけがそれぞれの速さで聞こえること、連打でも重ならないこと、次の問題へ進むと停止することを確認します。
5. アプリを閉じ、機内モードにしてWi-Fiもオフにし、ホーム画面から再起動。問題表示、解答、正解音、次の問題への移動を確認します。英文の読み上げは端末内の英語音声の有無などに依存し、オフライン再生を保証しません。
6. オンラインへ戻し、更新版を配信後に再度開きます。途中で勝手にリロードせず、更新ボタンを押したときだけ新版になることを確認します。

## テストと制限

`tests/game.spec.js` は誤答後の再挑戦、未正解の次へ禁止、重複加算防止、20問完了、シャッフル、音声APIの英文・速度・en-US優先・停止呼び出し、効果音ON/OFFの発音ノード、スマホ/PC幅、manifest/アイコン、キャッシュ後のオフライン起動・解答、worker更新待機と旧キャッシュ削除を検証します。更新テスト用サーバーはworkerの版だけを切り替え、ソースを書き換えません。画面のエラーと404もゲーム一周のテストで監視します。

音声API呼び出しのテストはモックを使います。実際の聞こえ方・発音品質・端末の再生制限、iPhone実機のホーム画面追加は別途上の手順で確認が必要です。プレイ中の進捗は保存しないため、再読み込みや更新で1問目に戻ります。効果音設定だけを端末内に保存します。

現在環境での実行結果と公開状況は `VALIDATION.md` を参照してください。
